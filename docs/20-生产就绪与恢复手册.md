# 运行检查、升级与恢复

安装和升级入口见[自托管安装](../deploy/README.md)。当前开源分支使用通用 Compose，不需要私有发布菜单或指定服务器。

## 健康与就绪

API `/health/ready` 检查基础设施，使新安装可以先进入设置页，再配置模型。平台生产就绪检查进一步报告密钥、网络、队列、Worker、存储、真实生成和图文安全状态；它不能被基本 HTTP 200 替代。

CAP、邮件、短信、小程序和公开指标按启用状态检查。未开启的可选接入不应阻断首次使用；启用后必须配置有效的凭据与安全参数。生成仍受真实模型、审核、资料、权限门禁约束。

```sh
pnpm production:audit
```

运行此命令需要当前环境的依赖配置和访问权限。输出可以包含运行元数据，向外提供前复核脱敏，不把完整环境文件或业务日志上传到 issue。

## 故障处理

- 先检查 API 与 Worker 的健康、队列积压和具体工作项状态，避免盲目重复生成产生额外费用。
- 资料待补充、模型失败、安全审核阻断与存储容量不足分别处理。
- 外部回读异常保持待复核或技术状态，不认定员工未发布。
- 分享诊断仅提供必要的错误码、时间和匿名操作步骤；去掉请求正文、签名 URL、Token、手机号、邮箱与客户资料。

## 升级与数据保护

1. 在本机或构建机生成明确版本镜像，验证兼容性后交付到运行机。
2. 保留现有数据库、对象存储和加密主密钥，先执行兼容迁移，失败时停止后续切换。
3. 启动已有镜像并检查健康与关键业务。不要使用 `up --build` 在生产运行机现场编译。
4. 保留可回滚镜像及迁移回执；不篡改已完成迁移，不用 `db push`、清空数据或 `down -v` 代替升级。

本项目不自动复制或备份业务数据。恢复必须依据使用者已经验证且有权限使用的恢复材料；未验证的运行中数据目录拷贝不能称为一致性备份。不要为检查命令擅自重建已有业务库。
