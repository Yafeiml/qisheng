# 动态模型门禁

功能验证不再按 24 小时失效。首次接入、模型／地址／密钥等配置变化、开发和生产模式切换仍需要验证。历史 `expiresAt` 和运行策略 TTL 字段仅保留兼容，不再决定是否允许生成。

## 触发与恢复

- 文案、生图分别统计同一路由、同一配置、同一运行模式下的任务结果。
- 连续 **3 个独立任务**最终因模型调用失败，且每个任务有**至少 2 个不同执行轮次的实际失败调用记录**，才阻止受影响路由的新生成任务并要求复验。同一任务重复入队、同一轮内重复请求不会凑成门槛。
- 单次网络失败、进行中的重试不会触发功能复验。队列容量、限流、存储、数据库、内容审核和租约失效不计为模型故障；没有上游调用证据也不计数。
- 同一能力的成功任务清零该能力的连续失败数；成功功能复验开始新的观察周期。失败复验不能回退使用更早的成功记录。配置变化后旧故障关闭，新配置仍需首次验证。
- 原有供应商短时调用保护继续存在：默认连续 5 次调用异常后冷却 60 秒，通过带租约的探测自动恢复；这不等于功能验证失效。容量和限流拒绝不会增加其失败计数。
- 自动连接探测只用于诊断，单次失败不会使已通过的功能验证失效。当前已排队任务继续执行既有重试策略；不取消既有活动、不影响已生成内容或其他功能。

## 页面与通知

平台「模型配置」显示运行状态、文案／生图连续失败数及邮件发送状态，可手动执行功能验证或重试邮件。门禁状态页将单次连接异常显示为「诊断提醒」。

集团和企业后台顶部显示生成异常提示；集团只统计该集团内受影响的企业。企业专属路由优先于集团路由，再优先于平台路由。响应不包含供应商地址、凭据、任务正文或其他客户信息。页面每分钟刷新，切回页面时也会刷新。

在平台「通知设置」配置 **模型故障接收邮箱** 和可选 SMTP 服务。发件地址、SMTP 主机、授权密码等共用已有配置，与「小程序设置」的员工任务订阅通知开关独立。

后台每 30 秒检查。事件持久化到 `model_route_incidents`，按路由和运行模式唯一，多 API 实例共享发送租约。同一轮故障成功发送后不重复发送；恢复后再次出现故障是新一轮通知。

- 邮件服务确认接受目标收件人后，才显示「已通知平台管理员」。这表示 SMTP 已接受，不保证邮件已进入收件箱。
- 配置缺失：显示未配置，每 5 分钟重新读取设置，不消耗发送次数。
- 发送失败：指数退避，最多自动尝试 5 次；耗尽后提示修复配置并点击「重试邮件通知」。
- 进程中断：发送租约 120 秒后可由其他实例接续。SMTP 接受后进程恰好崩溃仍可能重复提交，固定 Message-ID 用于协助去重，不承诺邮件传输绝对仅一次。
- 开发模式不自动发送真实故障邮件，也不会自动执行计费功能验证。

## 验证与发布

后端与迁移测试使用隔离临时数据库，所有模型和邮件调用均为本地协议服务或模拟：

```bash
node scripts/dev/test-model-gates.mjs
./scripts/dev/pnpm.sh exec playwright test --config tests/e2e/playwright.models.config.ts
```

新增两项兼容迁移：`20260926010000_dynamic_model_incidents`、`20260926011000_dynamic_model_incident_indexes`。仅新增故障记录表和索引，不修改既有资格记录或密钥。

当前安装与升级统一见[自托管说明](../deploy/README.md)，使用兼容迁移和已构建镜像。本文不授权任何生产部署。
