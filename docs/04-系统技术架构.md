# 系统技术架构

当前实现是 TypeScript workspace 中的模块化单体与后台 Worker，默认用一个 Compose 项目交付，不要求指定云厂商或主机拓扑。

| 部分 | 位置与职责 |
| --- | --- |
| Web | `apps/admin-web`：平台、企业及正式员工网页 |
| API | `apps/api`：权限、资料、活动、回填和平台治理 |
| 内容 Worker | `apps/worker`：资料解析、生成、生命周期与后台任务 |
| 共享包 | `packages`：AI 路由、安全、存储、数据库和接口契约 |
| 微信小程序 | `apps/employee-miniapp`：可选员工接入，不是安装前提 |

## 基础设施

- PostgreSQL 保存业务事实、不可变快照、审计和索引；迁移要求相应扩展，见[安装说明](../deploy/README.md)。
- Redis 与 BullMQ 承载验证码、限流、任务队列、租约和短期状态。
- 默认本机存储保存原始资料和生成图片，也可配置 S3 兼容私有对象存储。原文件只通过受权限约束的交付方式访问。
- 模型供应商由平台管理员配置。业务代码声明能力，由统一路由选择；密钥加密保存，消费者不把秘密写入活动快照。

不配置外部向量模型时可使用基础本地字符检索；它不被宣称为语义检索。文本、图片生成和图文审核仍需真实可用的模型能力。

## 安全与一致性

管理与员工 Token audience 隔离，访问检查包含工作空间、企业和成员范围。外部网络请求执行协议、DNS、重定向及响应体大小检查。素材授权、有效性与私有对象读取在使用时校验，不能只信任创建时的快照。

业务写入使用事务、幂等键、工作项状态转换和租约，避免重复排队造成重复生成或交付。生成失败、审核失败、外部验证异常分别处理。

## 交付

用 `deploy/self-host.mjs` 初始化私有配置和在本机或构建机生成明确版本的镜像；运行机只使用已有镜像执行迁移与启动。当前 Compose 不含源码构建钩子。安装、HTTPS 和升级以[自托管安装](../deploy/README.md)为准。
