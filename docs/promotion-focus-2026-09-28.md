# 可选宣传重点（2026-09-28）

## 用户流程

- “内容规范 → 宣传重点”替代“品牌实体”。保留历史数据和版本，不强制配置。
- 从当前企业可访问的已授权、生效、已完成分析且可用的资料中读取对象推荐，不额外调用 AI。图片按附件读取分析，忽略待补充图片及 Logo；忽略仅由文件名猜测的名称。
- 推荐展示来源和依据。用户确认时可编辑名称、其他称呼和类别，选择企业专属或有权管理的集团共享范围。确认后仍可编辑，内部沿用版本化保存。
- 用户问题按需单独维护；名称和称呼不是资质、功能或其他事实的证明，生成仍须检索品牌资料。
- 创建活动根据传播要求中明确出现的名称或称呼匹配宣传重点；用户可勾选调整、恢复自动匹配或“本次不指定”。没有宣传重点不阻止生成。
- 草稿保存手动选择及明确空选择。复制新活动时按重点系列映射到当前有效版本，历史活动快照不回写。
- 覆盖分析只说明本系统的活动与生成文案，不代表外部排名或曝光。未使用重点不提示为错误；可选设置不再显示成必须达到的资料完整度评分。

## 技术约定

- `CreateCampaignDto.focusEntityIds`：省略表示自动匹配，`[]` 表示不使用；最多 20 个，不允许重复、null、失效版本或跨范围 ID。
- 检索只扩展选定重点的名称、别名与关联问题，不再拼入全部启用实体。集团共享能力关闭时不查询集团重点；同名同类重点沿用企业优先规则。
- 检索返回 `focusOptions` 和 `focusEntityIds`。活动生成及生成测试台将实际选中 ID 传入生成上下文，再冻结到原有 `sourceContext.assetSnapshot.geoEntities`；未显式传入选中 ID 的上下文默认没有重点。
- 推荐接口 `GET /console/tenants/:tenantId/enterprises/:enterpriseId/focus-recommendations` 要求 `geo.read` 和 `material.read`，是只读请求。确认沿用已有写入接口、权限与容量限制。
- 保留数据库/API 内部 Geo 命名及历史类型枚举。`DOCTOR` 在新界面呈现为“人物”，`DEVICE` 为“产品 / 设备”，避免为通用行业支持改写既有数据。
- 无新数据库迁移，无 Worker 协议变更；历史活动与已有 Worker 冻结输入格式兼容。

## 验证与发布

使用本地 fixture / mock provider 检查名称与别名匹配、无重点、企业覆盖、权限范围查询、资料有效性、草稿保存、复制及既有活动生命周期。浏览器覆盖 1440px 与 390px 的推荐确认、二次编辑、选择状态、草稿恢复和提交。
