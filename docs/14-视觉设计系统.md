# 视觉设计系统

## 1. 设计方向

企声发布采用“暖白编辑部 + 企业内容中台”的视觉方向。系统需要让运营人员感受到小红书内容生产的生活方式色温和编辑感，同时保持企业长期使用所需的可信度、数据密度和权限清晰度。

代码实现以 `apps/admin-web/app/styles.css` 为准。

## 2. 语义色彩

```css
:root {
  --bg: oklch(0.985 0.014 78);
  --surface: oklch(0.998 0.006 82);
  --surface-warm: oklch(0.958 0.026 73);
  --surface-rose: oklch(0.945 0.043 18);
  --fg: oklch(0.19 0.015 42);
  --muted: oklch(0.48 0.025 48);
  --border: oklch(0.87 0.027 58);
  --accent: oklch(0.55 0.19 24);
  --accent-ink: oklch(0.35 0.14 24);
  --accent-soft: oklch(0.91 0.055 22);
  --lemon: oklch(0.86 0.13 92);
  --mist: oklch(0.78 0.065 225);
  --success: oklch(0.56 0.13 145);
  --warn: oklch(0.69 0.15 74);
  --danger: oklch(0.55 0.18 28);
}
```

- 大面积区域只使用暖白、奶油白和浅胭脂粉。
- 莓果红只用于当前导航、主要操作和关键强调，同一屏不应出现多个竞争性主操作。
- 柠檬黄表示额度、排队和待处理；雾蓝表示数据作用域、趋势和模型路由信息。
- 成功、警告和危险状态必须同时依靠文字，不得只依赖颜色。

## 3. 排版与布局

- 中文统一自托管 `Noto Sans SC Variable`，避免开发机字体差异和中文缺字。
- 页面主标题为 27–40px、600 字重、至少 1.32 行高；正文为 14–15px、1.7 行高。
- 桌面侧栏约 248px，工作区使用可用宽度；面板圆角 8px，输入和按钮高度不低于 44px。
- 管理端优先使用紧凑网格、排行、流程和表格，不使用营销页式大留白或卡片套卡片。
- 内容封面可以使用贴纸、短标题、轻微旋转和独立构图，但不使用幼稚插画或表情图标。

### 区块与表单间距

- 后台 `.appWorkspace` 的独立区块统一保留 `--space-page: 18px` 上下间隔，覆盖指标、筛选、提示和卡片的混排；不将该规则递归施加到表格、行内标签和紧凑列表。
- 抽屉表单 `.drawerForm` 和独立纵向表单 `.formFlow` 由容器的 `--space-form: 16px` 管理间距，直接子项不再叠加外边距。提示信息、说明卡、复选项与危险操作按钮遵循同一规则。
- 网格已有 `gap` 时，不再叠加通用 `.panel + .panel` 外边距；同排卡片顶端对齐，切为单列后保留一次间距。
- 图片与独立操作使用 `--space-control: 12px` 间隔。紧凑表格内的控件、标签与正文行距仍由局部样式控制。
- 表单按钮默认按内容宽度显示，只有显式 `.block` 或移动端设计需要时才占满整行；必须检验焦点、选中、禁用和提交反馈，避免网格拉伸按钮。

间距回归入口为 `tests/e2e/playwright.spacing.config.ts`。定点表单用例完全模拟接口；`site-spacing.spec.ts` 则只读遍历已有本机演示会话（需 `.artifacts/mvp-storage-state.json`），自动发现后台路由、参数分组和页面 tab，测量桌面及窄屏区块间距。禁止为间距检查运行会清理业务数据的全量演示初始化。风格抽屉另由 `playwright.styles.config.ts` 回归。

## 4. 响应式规则

- 390、768、1024、1440px 是持续回归宽度；360、430、600、820、1366 和 1920px 应遵循相同布局约束。
- 单列网格必须使用 `minmax(0, 1fr)`，网格子项和面板必须允许 `min-width: 0`。
- 表格最小宽度只能由排行或路由表格自身的滚动容器承接，禁止产生页面级横向滚动。
- 1040px 以下侧栏变为顶部横向导航；700px 以下指标、表单、审批和手机预览改为单列。
- 微信小程序以 390px 为主要宽度，在桌面评审页中使用手机框；正式小程序继续按微信组件体系实现。

## 5. 交互与可访问性

- 所有链接、按钮、输入框和可滚动数据区域必须具备清晰的键盘焦点。
- 按钮按下仅下移 1px；动效控制在 120–180ms，并尊重 `prefers-reduced-motion`。
- 默认、悬停、选中和禁用状态必须保持文字可读，不使用低对比度灰色隐藏重要信息。
- 员工端必须持续明确“仅本人任务、本人内容和本人历史”，不得出现其他员工列表或企业排行入口。

### 复选框统一规范

- 全站原生 `input[type="checkbox"]` 共用 `styles.css` 中的规则：`--checkbox-size: 16px`、2px圆角、未选中白底灰边、选中品牌红底白勾。不得继承文本输入框的44px高度或内边距，也不在页面/模块中重复定义尺寸。
- 保留原生label点击、Space切换、表单值和禁用语义；部分选中使用 `indeterminate` 横线，员工表头随可选择行的选择情况更新。
- 单行文案和表格行居中对齐；带说明的组织映射、参与锁定选项与首行主文案对齐。输入本体保持16px，label仍提供完整点击区域。
- 禁用透明度只在复选框本体应用一次，不能与外层卡片重复衰减。键盘焦点使用2px轮廓；高对比模式恢复原生系统外观；减少动态效果模式关闭颜色过渡。
- 参数中心启用/停用、筛选等 `aria-pressed` 按钮不属于复选框，不应被替换为方框。

专项回归入口：`./scripts/dev/pnpm.sh exec playwright test -c tests/e2e/playwright.checkbox.config.ts`。覆盖16个复选框模板位置的桌面/窄屏页面与抽屉、选中/半选/禁用、键盘和模拟提交；来源清单测试会提醒补充新增控件的覆盖。所有业务接口均模拟，不发送真实短信或调用付费模型。

## 6. 禁止项

- 深绿色整面侧栏或大面积深色工作区。
- 紫蓝渐变、廉价霓虹、大面积玻璃拟态和过重投影。
- 泛滥圆角、胶囊按钮、彩色状态标签和多层卡片嵌套。
- 为了“小红书感”直接复制小红书 App 的导航、图标或页面结构。
