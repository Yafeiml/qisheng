# 素材自动整理与生成召回

2026-09-10：新增资料简化为粘贴文本、粘贴图片或批量上传文件，不再要求标题、标签或来源类型。上传后关闭抽屉，后台继续分析。公开链接的新建、更新抓取和重试入口不在前端开放，原有链接 API 与已存快照预览保留；粘贴 URL 不会自动抓取网页。

## 调用目标

活动主题如“门店周末体验活动”，通过关键词、正文和已启用的检索方式召回相关服务、环境和图片说明。AI 生成的关键词包含有依据的实体名称及简称，并写入素材标签与索引文本。图片资料的识别描述、OCR 文字和用户说明进入现有生成上下文；本次没有新增原图合成或人物换脸功能。

检索候选对中文关键词做明确包含匹配，之后仍按混合评分和作用域筛选。资料分别保存，不因同批上传或同一主题被召回就推断人物与项目的业务关系。图像理解不依靠人脸推断姓名、职称或医院；文件名只作线索。

## 状态与补全

- 入库任务沿用 PENDING / PROCESSING / READY / FAILED / QUARANTINED。
- 资料新增独立 usabilityStatus：PENDING / USABLE / NEEDS_INPUT。
- 识别完成但缺少关键信息：任务 READY，资料 NEEDS_INPUT，无可引用索引，页面显示“待补充 · 暂不用于生成”。
- 识别充分且索引完成：任务 READY、资料 USABLE。所有检索分支、显式资料生成上下文及活动就绪统计共同检查可用状态、授权、启用状态和有效期。
- 模型异常、超时或非法输出属于技术失败，最多自动重试五次；不伪装成资料缺失或处理成功。
- 尚未上传完毕的文件显示“等待上传完成”，不计入 AI 处理中。

补充入口只要求一句具体说明，可修改已填说明。待补充资料在原版本上继续分析；已可用资料创建不可变新版本，引用原始文件对象，不再次上传或重复占用存储。新版本可用前保留旧版本，新版本完成后切换；历史活动与旧索引不被改写。重新分析重新生成关键词，不保留已纠正的旧 AI 标签。

## 平台模型配置

“平台模型 API 与路由 → 模型用途”提供“资料理解模型”配置入口，可直接登记支持 TEXT + VISION 的模型并选择使用；与平台参数的检索设置共用“资料理解模型”（retrieval.material_analysis_model_id / RuntimePolicy.materialAnalysisModelId）。可选已启用的真实多模态模型，或同时声明 TEXT 与 VISION 的兼容模型。留空沿用平台文案主模型，处理图片仍要求 VISION 或 MULTIMODAL 能力。

未配置真实可用模型时明确失败，不使用演示描述假装 AI 成功。图像通过现有受控兼容 Provider 传入压缩后的图片字节；文本按有重叠的窗口完整分析，不静默截掉文档尾部。长任务持续续租。模型凭据仍只在服务端读取。

既有人工维护的素材保留原有可用性，不自动重跑；新建及补全任务使用 material-ai-v2。原始文本、补充说明、分析结果与派生索引分开存储。

## 验证重点

- 无标题、无标签创建文本和文件。
- 随机文件名的人物照即使模型声称完整，也必须有身份依据才能调用。
- 文件名身份、虚构实体证据和非法模型输出不能直接放行。
- 服务、产品及图片资料在无关资料干扰下被同一主题召回。
- 补充前自动召回与显式调用都排除图片，补充后无需重传即可引用。
- 更正身份后重建关键词；旧版本与历史引用保留。
- 浏览器验证混合上传、失败文件单独重试、状态自动刷新与四种屏幕宽度。

## 模型配置页面

模型页面按“接入服务商 → 登记模型 → 指定用途”组织，分为模型用途、服务商连接、模型目录三个视图。默认目录展示正式接入；开发演示和由项目测试生成的已知名称/编号组合单独归类为“开发与测试”，保留原始配置和路由。不会仅凭名称含 test 或 Sprint 就隐藏用户连接。API Key、连接测试与高级维护集中在连接详情中，成本和内部编号放入高级设置。
