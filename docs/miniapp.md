# 员工微信小程序自部署

员工微信小程序是企声发布的可选客户端。企业可以使用自己的微信小程序账号，连接自己部署的企声发布服务；没有微信小程序账号时，直接使用员工网页 `/employee` 即可。

本文对应 v0.1.1。主服务安装见[部署与常见问题](deployment.md)，业务流程见[操作说明](user-guide.md)，客户端位于 [apps/employee-miniapp](../apps/employee-miniapp/README.md)。建议主服务和客户端使用同一固定版本。小程序源码包不是已编译、已上传微信或已通过审核的制品。

## 1. 准备自己的服务和微信应用

1. 按部署说明启动主服务，完成网页中的管理员与组织设置。
2. 为小程序准备自己的公网 HTTPS 站点，例如 `https://qisheng.example.com`，确保站点及 `/api` 均由反向代理交给企声发布 Web 服务。不要把小程序连到 Docker 内部的 `http://api:3100`。
3. 使用自己的微信小程序账号，取得真实 AppID 和开发者工具导入、预览、上传所需权限。源码里的 `touristappid` 只是模板占位。
4. 在企业工作台添加参与员工、启用任务资格，为成员创建员工网页账号。先通过 `/employee` 验证该账号可登录。

网页首次安装仍可通过服务器 IP 加端口完成，域名不是安装前提。正式微信小程序的网络规则另行适用：需要配置自己的 HTTPS 合法域名，不能直接沿用公网 IP。微信官方文档还列出域名备案、证书及端口要求，应以自己的微信后台和[网络通信说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)为准。

默认账号密码登录不需要短信、微信 AppSecret 或订阅消息配置。系统不开放员工自行注册；仅有后台管理员权限、但没有有效员工身份的账号不能领取他人的任务。

## 2. 导出配对后的独立项目

### 从完整仓库导出

在构建或开发电脑上准备本版本完整源码和 Node.js 24，进入源码根目录。将以下三项替换为自己的值，输出目录使用尚不存在的新目录，其父目录须已存在：

```sh
node scripts/miniapp/export.mjs --app-id "替换为自己的AppID" --api-base "https://qisheng.example.com/api" --output "../qisheng-employee-v0.1.1"
```

命令可在 PowerShell 或支持 Node.js 的终端执行。`qisheng.example.com` 是示例，不提供实际服务。`--api-base` 是带 `/api` 的 API 前缀，通常使用与网页相同的站点，便于本机存储图片经同一 HTTPS 地址交付。

工具生成新的独立项目，并写入该副本的 `config.ts` 和 `project.config.json`；不修改主服务配置，不执行微信上传或发布。保留仓库通用模板，为测试和正式环境分别导出新目录，避免在同一目录反复切换实例。

### 使用独立小程序源码包或手动配置

直接下载 [v0.1.1 独立小程序源码 ZIP](https://github.com/Yafeiml/qisheng/releases/download/v0.1.1/qisheng-employee-miniapp-v0.1.1.zip)。先查看同一 Release 的 [SHA256SUMS.txt](https://github.com/Yafeiml/qisheng/releases/download/v0.1.1/SHA256SUMS.txt)，将下载文件的 SHA-256 与对应文件名条目比对后再解压。PowerShell 可用 `Get-FileHash -Algorithm SHA256`，Linux 可用 `sha256sum` 计算本地文件的校验值。

解压后先确认项目根目录含 `app.json`、`project.config.json`、`config.ts` 和 `pages/`，并保留 `LICENSE`、`NOTICE` 及随包第三方许可。它是源项目，需由自己的开发者工具编译；仅有客户端源码的目录不能执行完整仓库中的导出脚本。

在独立副本中手动配置：

| 文件 | 需要填写的内容 |
| --- | --- |
| `config.ts` | `miniappConfig.apiBaseUrl`：自己的 HTTPS API 前缀，如 `https://qisheng.example.com/api`；保留默认 `smsLoginEnabled: false`。 |
| `project.config.json` | `appid`：自己的真实小程序 AppID。 |

确认开发者工具“详情”显示的 AppID。原生编译、预览及真机验收必须使用自己的有效 AppID，`touristappid` 仅为占位。已有 `project.private.config.json` 可能优先于通用配置生效，不要复制上一个项目的私有配置。配置优先级见[微信官方说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。

API 地址与 AppID 是部署信息，可以出现在客户端；AppSecret、模型密钥、数据库密码、安装凭证和用户密码都不能打包进客户端或发到公开仓库。服务端凭据由部署者在自己的后台填写。

## 3. 微信后台与开发者工具

### 请求与图片下载域名

在自己的微信公众平台“小程序后台 → 开发 → 开发设置 → 服务器域名”中，按实际交付地址配置：

| 类型 | 当前客户端用途 |
| --- | --- |
| request 合法域名 | `miniappConfig.apiBaseUrl` 所属 HTTPS 站点，调用登录、任务和回填 API。 |
| downloadFile 合法域名 | 实际任务图片下载地址；默认本机存储通常与站点同域，S3 或其他交付地址按实际主机补充。 |

当前客户端没有 `wx.uploadFile` 步骤，无需为它单独设置文件上传域名。HTTPS 证书须有效且与域名一致，协议、主机和端口须符合微信规则。图片签名 URL 是短期授权地址，不要公开或改成匿名存储链接。完整规则见[微信网络通信说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

### 导入、编译与预览

1. 安装微信官方开发者工具，使用有该应用权限的微信账号登录。
2. 导入独立项目根目录，选择自己的 AppID，确认目录含 `app.json`。连接自托管 API 不要求开通云开发；不要导入整个企声发布仓库作为小程序根目录。
3. 保留项目 TypeScript 编译插件设置，点击编译，检查登录页及控制台错误。
4. 确认 HTTPS 地址、合法域名和证书后保留域名校验，通过工具“预览”在真实手机微信中验证。
5. 通过下文验收后，再使用自己的开发者工具上传代码，在自己的微信公众平台管理开发版本、体验及后续审核发布。按账号实际权限操作。

工具的编译、预览、缓存清理和上传入口见[官方界面说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/page.html)。导出脚本和源码包不执行这些账号操作，也不保证通过微信审核。

### 用户隐私与相册权限

按实际使用的信息和能力，在自己的微信小程序管理后台填写《小程序用户隐私保护指引》，提供部署者自己的联系方式和相关说明。员工账号、任务数据、可选手机号和微信消息身份按实际启用情况说明；源码中的业务提示不能替代完整隐私指引。

保存图片使用 `wx.saveImageToPhotosAlbum`，需要用户相册写入授权。微信提供官方隐私授权弹窗；用户拒绝后不要反复强制弹出。使用自己的应用验证首次同意、拒绝和再次操作。官方依据见[小程序隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)和[保存图片 API](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.saveImageToPhotosAlbum.html)。

## 4. 员工登录与日常发布

员工使用管理员创建的员工网页账号密码登录。客户端验证账号后换取员工访问令牌，只显示本人当前可用的成员身份与任务。集团多企业权限按成员范围生效，不因使用同一小程序就能查看所有企业。

每次按任务中的当前版本操作：

1. 查看任务并领取内容。
2. 确认事实、图片授权和发布安排符合本人真实情况；不符合时退回管理员。
3. 确认通过后复制文案、保存分配图片。内容或授权变化时，重新取得当前内容并确认。
4. 自行打开小红书，使用自己的账号手动发布，不向本系统提供小红书账号密码。
5. 回到任务粘贴发布链接并提交，等待人工复核；管理员按需启用自动回读。

小程序不会代替员工自动发帖。已退回、未确认或版本变化的内容不能复用原授权；任务未开放时不提前交付图文。发布规则、业务资料和隐私授权仍需企业及员工按实际情况核实。

## 5. 可选短信登录与微信订阅通知

### 短信登录

默认隐藏手机号验证码入口。确需此流程时，在导出命令加 `--sms-login`，或将独立副本 `config.ts` 的 `miniappConfig.smsLoginEnabled` 改为 `true`，重新编译和验收。

同时在企声发布后台配置自己的短信服务并验证真实送达，按需配置 CAP。短信验证只绑定本人手机号对应的有效员工成员，不开放自由注册，不凭未验证手机号认领身份。没有配置真实短信服务时，保留账号密码登录即可。临时调试验证码不是正式员工认证方案。

### 微信新任务通知

任务通知默认关闭，与账号密码登录分开。需要时由主管理员配置：

| 后台项 | 填写要求 |
| --- | --- |
| 微信小程序 AppID、AppSecret | 使用当前自己小程序的凭据，AppID 与开发者工具及微信后台一致；AppSecret 只在服务端保存。 |
| 任务通知渠道 | 启用任务通知，选择微信小程序订阅消息。 |
| 订阅模板 ID、字段映射 | 使用自己微信后台已添加模板的实际 ID 和字段，按后台说明填写映射。 |
| 小程序版本环境 | 与实际开发、体验或正式版本一致。 |

员工登录后，客户端调用微信登录接口连接自己的通知身份，再由员工主动点击订阅。客户端不提交自行编造的 OpenID，服务端按当前应用凭据换取微信身份。一次性订阅拒绝或送达失败，不影响任务、发布与回填。

使用真实应用和有权使用的测试员工验证授权及实际送达后，再启用正式通知；不能只凭后台保存成功或本地测试通过就宣称通知可用。没有通知需要时，不填写 AppSecret，也无需开启渠道。

## 6. 真机验收与常见问题

首次交付至少用自己的应用和测试员工核对：

- 正常密码可登录，错误密码被拒绝；未绑定或已停用成员不能取得任务权限。
- 能领取本人任务，开放前不交付内容；未确认、退回及内容改版时不能继续复制旧图文。
- 真机能下载并保存图片；拒绝相册或隐私授权时显示错误，恢复授权后可重试。
- 手动发布后能回填链接，默认人工复核流程可完成。
- 退出后不能继续使用旧界面；切换实例或客户端配置后重新登录，不显示另一实例的旧任务。
- 如启用短信或订阅消息，单独核验真实验证码、本人身份关联和消息送达。

| 问题 | 处理方法 |
| --- | --- |
| 仍是模板地址或旧 AppID | 检查实际导入目录、`config.ts`、项目详情及 `project.private.config.json`。重新编译，必要时清理工具缓存。 |
| 请求域名不合法 | 核对 API 的 HTTPS 域名及端口，配置到自己的微信后台；确认正式预览没有跳过校验。 |
| 页面可用，图片下载失败 | 检查 downloadFile 合法域名、实际图片地址、证书、存储状态及签名有效期；重新打开任务取得新地址。 |
| 后台可登录，小程序无员工身份 | 管理权限与员工身份不同。请管理员在正确企业创建或启用该成员的员工账号，先验证 `/employee`。 |
| 手机号入口不显示 | 默认用账号密码。确需短信时启用 `smsLoginEnabled` 并配置自己的短信通道。 |
| 换地址后登录失效 | 各实例分别登录，不复制旧令牌、私有配置或缓存；核对客户端与主服务版本。 |
| 小程序与通知配置不匹配 | 核对当前 AppID、服务端 AppID、AppSecret 和模板所属应用，再重新准备通知身份。 |
| 通知暂不可用 | 任务可照常处理。检查渠道、凭据、模板、环境及微信接口错误，不把 AppSecret 或完整日志发到公开 Issue。 |
| 相册保存失败 | 检查自己的隐私指引声明及用户相册授权。不要绕过拒绝；按微信设置重新授权后重试。 |
| 工具可用，手机不可用 | 手机的 `127.0.0.1` 是手机本身，检查本地地址、被跳过的域名校验、证书和公网可达性。 |
| 没有上传或体验权限 | 确认自己的真实 AppID、当前微信账号权限，到自己的微信后台处理；模板 AppID 不能代替。 |

### 本地开发与升级附注

只有维护者调试本地服务时，才临时使用本地 API 并关闭工具域名校验。按[源码 README](../apps/employee-miniapp/README.md#校验与验证码产物)准备开发环境；手机须使用实际可达地址，不能使用电脑自己的 loopback。正式预览和上传前恢复自己的 HTTPS 配置，重新验收。

`scripts/dev/sync-miniapp-windows.sh` 是 WSL 与 Windows 间同步源码的可选维护脚本，需要 `wslpath`、`rsync`，保留已有 `config.ts`、AppID 和项目私有设置，更新其他客户端源码。普通部署者直接导入导出的 Windows 可访问目录即可。

升级时先导出新版本到新目录，用自己的配置重新编译和验收，再按自己的微信账号流程上传。小程序更新与服务端镜像更新分开进行；导入或编译小程序不需要重新初始化主服务，更不要清空数据库。
