# 组织、角色与权限

`Tenant` 表示工作空间，`Enterprise` 表示其内部企业。管理账号、自然人员工身份与企业成员身份分别管理，避免把企业成员权限扩展到其他企业。

## 安装与登录

- `/setup` 仅在尚未初始化的安装中创建主管理员与组织，`/login` 是管理端账号密码登录入口。
- 一套安装服务一家企业或一个集团。首位管理员获得系统及相应组织权限，已有账号或组织不能再次初始化。
- 不提供公开注册，也不允许通过注册新建独立客户工作空间。后续管理员和员工账号由获授权的管理员在后台创建。
- 旧手机号管理员可在受信终端运行 `pnpm accounts:set-password` 设置密码。工具只处理已有有效管理员，不新建管理员或授予角色。
- CAP 默认关闭；启用后由服务端验证，未配置必要字段时不能启用。密码与 CAP Secret 不返回前端明文。

| 身份 | 范围 |
| --- | --- |
| 平台管理员 | 平台设置、模型与工作空间治理 |
| 工作空间管理员 | 被授权的工作空间及其企业 |
| 企业管理员与运营角色 | 被授权的企业、资料、活动及审核动作 |
| 员工 | 本人有效成员身份对应的任务、图文、回填与历史 |

角色授权受作用域和操作权限校验，界面隐藏不是安全边界。API 每次检查账号状态、成员状态、参与资格和资源归属。

## 员工网页账号

管理员为具体企业成员创建网页账号并设置初始密码，账号绑定明确的成员身份，不按未经验证的手机号合并身份。员工 Token 与管理 Token 的 audience 隔离；拥有后台角色不等于自动拥有员工任务。日常操作以[用户指南](user-guide.md)为准。

员工停用、参与暂停、任务豁免继续按成员身份治理。旧组织同步记录保留，三方通讯录同步代码与配置入口已经退出当前版本。
