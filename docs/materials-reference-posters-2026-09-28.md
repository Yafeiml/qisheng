# 分离资料入口与参考图海报

## 用户确认的规则

- 文字资料接受粘贴文字及 PDF、DOCX、TXT、Markdown；图片入口接受 JPEG、PNG、WebP，并要求公共说明或逐图说明。
- 图片逐张理解。公共说明及同批文件清单提供背景，不要求其他照片的主体也出现在当前图片。每张图片独立保存描述、分析与可用状态；一张待补充不阻止其他有效图片建立索引。
- 人物、产品、设备、门店、环境、团队、活动、装饰背景均按用途判断缺失信息，不为通用场景强制索取姓名、型号或无关履历。
- 未移除的当前附件随更新保留；支持逐图修改说明、指定 Logo、移除和明确恢复历史附件。原对象不物理删除，历史活动引用保留。
- 运营输入是任务说明。AI 从资料中提炼主次重点，生成少字、留白明确的海报，可选择无字；不把任务描述、完整简介或技术资料直接搬到画面。
- 除明确要求风格转换外，提示模型保留真实主体特征，允许抠图、边缘柔化、光影及背景融合。
- Logo 不传给模型、不重绘、不独立 AI 审核、不进行偏差重试。2026-10-10 起，系统在模型预留的左上角安全区直接合成原图，保留 4% 边距、比例、颜色及透明度，仅按版面等比缩放；不单独绘制品牌底板。多版本 Logo 按该区域的底色自动选择清晰版本，只有一个时直接使用。
- 每份员工图文的文案与全部最终配图在合成后共同调用一次审核，附带有长度上限的事实依据。审核接口失败时保存成品并进入 REVIEW_BLOCKED，不能因为审核失败自动重新生图或付费重审；用户明确发起的修订是新的生成任务。

## 实现与兼容

`MaterialArtifact.metadata` 保存逐图 description、usage、analysis、usabilityStatus、analysisVersion，图像索引 chunk 记录 artifactId。无需数据库结构迁移。旧单图继续使用已有有效结果；旧多图资料可在页面点击“按图片重新整理”，沿用原文件与说明，不在发布时自动批量产生识别费用。

活动检索同时返回作用域内可用图片；姓名及已有别名参与匹配。默认推荐一张相关主图，可人工替换或增加至三张；企业 Logo 默认采用当前企业最近的有效标记，集团 Logo 只在明确选择时使用。选择保存在草稿中。创建后冻结附件 ID、校验和及对象位置，生成时再次验证所属租户与原始字节，历史版本归档不改变已创建活动的快照。

API 图片候选返回文件名、说明及可用用途，不暴露对象存储键。原文件查看始终使用受权限保护的预览接口。编辑、附件列表、预览同时只显示一个抽屉，返回后保留编辑草稿。

有参考图时通过 `/images/edits` 上传 multipart `image[]`；无参考图时使用 `/images/generations`。模型使用当前平台已配置的原始 model ID，不自动改成其他模型。参考图接口失败不能退回无参考图生图。为兼容 DNS 固定的 undici 传输，先将原生 FormData 编码为带 boundary 的字节，再发送。

图像理解与图像生成是不同步骤。现有照片缩略图和说明可供人工核对，模型对真实主体的保真程度仍需要真实样片验收。文档中的参考图协议来自 https://developers.openai.com/api/docs/guides/image-generation 。公开文档与第三方兼容网关的实际能力可能不同。

## 验证与发布

验证覆盖：图片请求的 multipart 字节和模型 ID；参考图失败不静默降级；Logo 合成像素与尺寸；单次整体审核失败保留成品；多图部分待补充仍有独立索引；租户隔离；图片与文档分别上传；附件移除、编辑后预览返回；参考图数量限制、Logo 选择、草稿恢复和提交；1440px/390px 页面及控件。

协议联调使用本地 HTTP 模型服务和测试租户，不冒充实际配置模型的真实成图验收。部署后仍需使用实际供应商完成真实参考图和海报效果验收。

安装与升级见[自托管说明](../deploy/README.md)。API、Web 与 Worker 应使用同一兼容版本，不能仅更新界面就假定参考图协议已生效。
